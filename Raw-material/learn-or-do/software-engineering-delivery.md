# 软件工程实践参考｜第 4–7 步

从原软件工程实践参考摘出。保留原有编号、实施交接说明和参考依据，供后续整理。

需要分片或跨会话推进时，用父 issue 承接本轮整体目标、工程依据、切片关系与进度；具体做法见[切片与 issue 记录](slice-issues.md)。已有规格与设计直接引用。

### 4. 选择并细化本轮切片

- **思考：**本轮最值得交付什么，或最需要验证什么风险？
- **切片与承接：**结合整体目标和代码现状，先给出候选切片的结果、完成条件与真实依赖，检查粒度并供用户 Review；已有拆分直接沿用。每片应能独立验证，并能在有限上下文内讲清和完成；多个独立关注点难以共同审阅时继续拆分。按[切片与 issue 记录](slice-issues.md)建立子 issue、选择当前片，临近实施再补足细节。
- **工作：**围绕一个可验证的用户结果或关键风险限定范围，可跨多个模块，也可针对单个模块做探索实验。沿用已有需求与设计，按当前任务及需要掌握的内容补足本轮细节。
- **场景与局部设计：**推演关键请求触发哪些业务判断与状态变化、产生什么结果、由谁负责，以及重要失败时会怎样。区分应用流程的编排、领域判断与外部交互，再细化必要的接口、数据、一致性要求与技术边界；按需要用结构、时序或状态示意表达。细化接口时，从调用者要完成的任务出发，检查相关复杂性是否在合适边界内消化，并明确输入、结果及必要的失败语义。
- **领域模型：**仅在当前问题需要时采用相关构件：稳定身份与生命周期可用实体表达，按值定义的概念可用值对象表达，必须共同保护的一致性规则可帮助确定聚合边界。业务规则简单时保持模型简单，不要求凑齐战术模式。
- **规格、方案与计划：**将本轮目标、范围、约束和验收条件整理为 Spec，记录解决问题的方案、必要结构与取舍，再安排 Plan 和任务清单。方案说明怎样解决问题及其理由，Plan 说明怎样推进和验证；两者按任务需要细化，理解现状不必产生实施计划。
- **依赖处理：**外部能力尚未实现时，可用接口约定或替身进行局部验证；记录假设、限制、首次真实集成验证的时机与通过条件。暂时无法真实集成时，明确证据缺口与后续安排，不把局部通过视为真实集成已通过。
- **结果：**本轮 Spec、必要设计与 Plan，能够说清“做什么、怎样算完成、哪些假设仍待验证”。

切片记录以 Spec 和 Modeling 为重心：展开本片用例、规则、约束与完成条件，再说明改动前后的职责与契约、实际静态结构、动态协作及关键机制；Plan 与验证结果作相应记录。用户应能看清本片改变了什么、怎样运作，不能只得到任务清单、修改文件名或测试报告。

### 5. 实现、验证与调整

- **思考：**行为是否正确？关键失败情况是否处理？设计是否连贯，理解与修改负担是否合理？
- **工作：**按已确认的要求与设计实现完整的最小链路，边编码边检验，按需持续集成与审查；根据证据修复缺陷、重构，并调整需求或设计。
- **恢复与记录：**从指定子 issue、本片记录、父 issue 和必要依据恢复，核对代码、依赖及验证状态后继续，不因换会话重做已完成的访谈或设计。沿途维护本片方案、Plan、实质变化、验证发现与复验结果、Review 结论；已有有效方案和授权直接沿用，不能只在结束时补一份结果摘要。
- **验证：**适用时将 Spec 的验收条件转为可执行检查，优先围绕稳定契约验证行为，按变更影响与风险选择必要的单元、集成或端到端检查；结合设计审查评价概念完整性与复杂性，并按项目约定检查代码可读性与风格。优先复用有效测试，必要的额外测试说明验证目标与依据；按需精简重复或脆弱的检查，保留有效覆盖。用新案例和反例检验规则与模型；重要规则涉及多个参与者或时间点时，推演相应的交错场景，不只检查一次调用。检查应能发现相关错误，不要求每项任务都配置全部测试类型。
- **反馈与变更：**根据验证发现的问题，按主体 Verify 指导处理缺陷、设计差异与约束疑问，返回相关需求、设计、计划或实现修正并复验。记录重大问题及处置结果，在阶段 Review 展示，不为使当前实现通过而自行放宽标准。
- **结果：**可运行的切片、相关验证与审查证据、更新后的必要材料；说明验收结论以及剩余问题和影响。

### 6. 交付并观察运行

- **思考：**是否具备发布条件？如何发现故障并恢复？是否产生预期价值？
- **工作：**按变更范围和风险准备环境、配置、数据迁移、发布与回滚安排；完成相关验证，发布后观察日志、指标与用户反馈。采用接口假设或替身的部分，交付结论应清楚说明真实集成的验证状态。
- **结果：**可使用的版本、必要的运行说明、发布与运行证据，或明确尚未满足的交付条件。

### 7. 复盘并推进下一轮

- **思考：**哪些假设被验证或推翻？下一步最值得做什么？
- **工作：**根据证据调整需求、模型、设计和计划，将发现的问题按需补入有效检查与文档。按风险与价值安排剩余功能、质量改进或集成验证，再选择下一切片；目标或边界改变时重新对齐，必要时安排迁移或退役。
- **任务进度：**将本片实际结果与证据、未验证事项及约定审阅状态回写记录，满足本片完成条件后再标记完成；同步父 issue 的进度与下一步。沿用既有子 issue，按真实依赖选择下一片，不把代码已写或已提交视为全部完成。
- **结果：**更新后的理解与下一轮计划，或明确的结束、迁移与下线安排。

贯穿全过程关注风险、质量、安全、版本与必要文档。每轮保留可验证的结果、获得的认识和明确的下一步；按当前验收条件与证据收束。
