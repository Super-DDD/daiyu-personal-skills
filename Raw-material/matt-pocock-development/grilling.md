# grilling

持续访谈用户，直到双方形成共同理解。把它画成一棵**design tree**，每个决定下面接着依赖它的其他决定。

按**轮次**推进。**frontier** 指所有前置决定已经确定的决定。问这些问题时，可以直接基于已有答案。在一轮里问完所有当前可问的问题，逐题编号并给出你的推荐答案。等待用户回答后，再进行下一轮。

一轮采用下面的格式。

```
❓ **Q1** - **<问题标题>**：<问题正文，可以有多段，也可以包含多个选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**：<问题正文，可以有多段，也可以包含多个选项>

➡️ <你的推荐答案>
```

把每道题写成用户回答「是」就接受你推荐答案的形式。

每轮用户的回答都会改变 design tree。已经确定的决定向外扩展 frontier，依赖它们的问题就可以问了。重新判断当前能问哪些，然后开启下一轮。某个问题如果依赖本轮另一道尚未回答的题，就放到之后的一轮。

查明**事实**是你的工作。当前可问的问题依赖环境中的事实时，例如文件系统或工具里的信息，派一个使用全新 context window 的 subagent 查清。能查到的事自己查。探索进行中，这项事实仍是未满足的前置条件，先问其余可问的问题，等 subagent 返回后再问依赖该事实的问题。**决定**由用户做，逐项交给用户，并等待回答。

当 design tree 的每个分支都走过、没有可问的决定，也没有未经说明的假设时，访谈就结束了。等用户确认双方已经达成共同理解，再据此实施。
