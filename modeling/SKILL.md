# Modeling

围绕用户指出的问题、对象和已有要求建立模型。先说明整体用途和关键关系，再深入会改变判断的部分。材料不足时，查证能取得的事实，并向用户说明仍缺的关键输入。

1. **理解现状。** 根据材料、代码或观察梳理关键组成、职责、关系和运行机制。用一个能代表当前问题的场景说明各部分怎样协作、状态如何变化、结果为何出现。
2. **推演设计。** 涉及拟议变更时，标明已知现状、假设和候选设计。用代表场景推演方案结果，说明关键取舍和适用边界。
3. **查证关键假设。** 对会改变结论的假设，先找证据，或推演能区分结果的场景。证据不足时，明确哪些结论仍依赖该假设。
4. **呈现模型。** 用稳定的术语、简洁的说明和必要的图或例子表达。按用户要理解的深度组织内容，先解释整体，再展开相关局部。

当模型能解释当前问题、推演代表场景并说明适用边界时，交付模型、依据和待确认的问题，然后结束本环节。需要改动实际产物时，由用户另行发起实施。

梳理软件系统的整体架构或跨模块职责时，按需读取[概要设计方法](../software-high-level-design/references/design.md)，重点看业务职责、模型边界和架构取舍。需要确定讲解深度或图示时，参照[理解与表达](../learn-or-do/preferences.md#理解与表达)。任务已有约定的记录位置时，按[记录与接续](../learn-or-do/preferences.md#记录与接续)更新。
