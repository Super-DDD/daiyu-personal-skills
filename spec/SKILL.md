# Spec

把用户提供的意图、需求或现有规格整理成本次任务的要求。复用已确认的内容，并从项目材料中核实适用的约束和接口契约。

1. 明确目标、范围、必须遵守的约束、要交付的结果和完成条件。把完成条件写成可观察的结果。用户明确要求遵守的设计决定列为约束。仍可调整的实现细节标为候选方案。
2. 按任务需要明确用户想理解或掌握到什么程度、由谁作关键决策，以及 Agent 可以自主开展哪些工作。学习目标可以用用户能解释、预测或尝试的具体事项表达。
3. 先澄清会改变范围或完成判断的歧义。无法从已有材料确定时，向用户说明缺口。其余待定事项标明状态。

交付一份简明的 Spec，并列出仍需用户确认的事项。复用已有且仍适用的确认，以确认的要求结束本环节。候选设计、执行计划和实施由用户选择对应的后续环节时开展。

需要约定用户的决策责任或 Agent 的自主范围时，参照[决策与自主推进](../learn-or-do/preferences.md#决策与自主推进)。任务已有约定的记录位置时，按[记录与接续](../learn-or-do/preferences.md#记录与接续)保存规格和待确认事项。
