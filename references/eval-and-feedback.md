# 样本评估与反馈

这是可选扩展，仅在用户需要提取实践样本、重复试用或比较版本时读取。普通创建或修改任务直接依据本次 Spec、实际产物和验证结果评估；无需先准备样本。只提取样本时使用第1节即可。

用用户认可的实践样本，检验 Skill 是否满足 Spec、是否好用，并通过反馈修正问题。按“准备样本 → 按关注深度试用 → 对照判断 → 反馈、修正与复验”推进。

## 1. 准备样本，明确基线

从实际任务与对话提取：

- **输入：**Intent 与相关材料，初始信息、后续澄清和用户确认的 Spec；区分已确认要求与待确认内容。
- **参考结果：**用户认可的完整产物或目标达成状态，注明认可范围；它不必是唯一正确答案。
- **主要过程：**关键交互、选择、修正与注意事项，保留重要失败和纠正。
- **判断依据：**来自已确认 Spec 的目标、约束、验收条件及设计要求，以及第3节的质量标准。

样本可来自未使用 Skill 的成功实践，也可来自使用 Skill 后修正到满意的过程。由用户 Review，确认能代表其思路后用于评估。可只提取样本，不立即创建或修改 Skill。没有真实样本时可先形成 V0，在实际使用中积累；自拟案例仅支持初步检查，不当作用户认可的实践样本。

## 2. 按关注深度试用

同一问题可使用同一版 Skill，分别按“关注结果”和“关注设计”独立试用，也可并行。先确定范围和 Intent，再分别确认对应 Spec 与执行安排，已有确认直接沿用。

| 关注深度 | 开工前确认 | 主要观察 |
|---|---|---|
| 关注结果 | 目标、范围、约束、交付预期、验收条件和自主执行边界 | 能否自主完成，符合原意并提供可靠结果 |
| 关注设计 | 在上述基础上，补充用户关心的关键结构、接口、运行过程及设计决策 | 能否解释并遵守设计约定，结构是否清楚、实现是否符合要求 |

两种关注深度都可由 Agent 自主实现；用户实时参与时只记录真实反馈，不代答。用户希望掌握设计，不意味着跟进每次修改。测试范围可以只覆盖关键环节，用户认为足够时结束，未覆盖部分注明。

保留各自实际输入、确认的 Spec、方案、关键动作和输出。记录不同规格深度与运行中新增的信息、用户纠正，不倒填为开场已知条件。若目标包含用户本人掌握，需要其解释、预测或应用表现作为证据。

## 3. 对照 Spec，判断差异与原因

每次试用按各自批准的 Spec 和 [设计原则中的评估标准](skill-design-principles.md#评估标准) 检查过程与结果：

分别说明 Spec 达成、概念完整性与复杂性的结论及证据。软件任务的代码风格和测试检查沿用通用原则，按本轮适用范围进行。

不满足 Spec 的内容作为缺陷报告；偏离已确认设计决策时说明原因、影响和建议处置，二者可能重叠。与参考结果比较时区分有效差异、缺陷和设计偏差，不能将未批准要求作为验收门槛。

分别给出结论和证据，再综合比较。说明不同规格深度、新增信息、用户参与、执行和环境对可比性的影响，不把条件差异直接归因于 Skill。未验证的原因标为推测，不凭一次运行判断某种关注方式普遍更好；参考结果不代替已确认的验收标准。

## 4. 反馈、修正与复验

默认给一份简洁主报告，说明 **Spec 达成情况、概念完整性与复杂性、设计偏差、原因依据、修改建议及复验结果**，列明用户需要决定什么。发现附少量原文或证据定位，没有必要修改时也可以建议不改。

需要附件时，证据按以下三类组织，原始文件按需链接。复用已有材料；没有对应内容的附件可省略，简短证据可直接纳入主报告：

| 文件 | 作用与读法 |
|---|---|
| 参考样本 | 保存认可的输入、结果和主要过程，核查原始预期时阅读 |
| 本轮运行记录 | 按关注深度分节，保存各自 Spec、完整输入、输出和主要过程 |
| 详细对比分析 | 保存逐项判断、证据、差异及归因依据，有疑问时查阅 |

参考样本与各次记录按“任务条件—输入—主要过程—输出—限制”排列，便于在 IDE 并排阅读。大文件链接原样副本，报告写清位置和阅读方式，日常不要求用户通读附件。

根据用户 Review 和已定位的问题，按授权修正 Spec、Work、资源、判据或展示。涉及规格或关键设计决策变化时先确认，记录原因，回查受影响的设计、用例和测试。针对修改复验，保留前后结果，更新结论并依约升版。已用于调整的样本用于回归，后续增加新样本检查适用范围。

## 执行注意

- 参考答案、历史后续纠正与评估结论不提前交给执行者；本来就应属于本轮任务输入的要求正常提供并记录。上下文已含评估参考时换用干净的执行上下文；无法隔离时标明条件，不声称是未见答案的重跑。
- 保留待测版本和真实记录，区分原文与摘要，说明缺口，不补造反馈或验证结果。试验产物与正式文件隔离，不覆盖参考样本。
- 满足约定要求或用户决定结束时收住；未达标、阻塞和未覆盖内容如实报告，不反复重跑直到得到满意结果。
