# 样本评估与反馈

用用户认可的实践样本，检验 Skill 在不同参与方式下是否好用，找出值得改进的地方。按“准备样本 → 两种方式运行 → 对照判断 → 用户反馈与修改”推进。

## 1. 准备样本，明确判据

从实际任务和对话中提取：

- **输入：**背景、意图、目标、预期、约束及原始材料。区分初始信息与后续澄清。
- **参考结果：**用户认可的完整产物或目标达成状态，注明认可范围；它不必是唯一正确答案。
- **主要过程：**关键交互、选择、修正及注意事项，包括重要的失败与纠正。
- **判断依据：**从 Goal 阶段已对齐的本次任务目标、预期、约束和验收条件中提取具体判据，并采用第3节的概念完整性与复杂性标准。需要补充或调整判据时，与用户确认。

样本可以来自未使用 Skill 的成功实践，也可以来自使用 Skill 后逐步修正到满意的过程。先由用户 Review，确认能代表其思路，再用于评估。可只提取样本，不立即创建或修改 Skill。

没有真实样本时，可先形成 V0，在实际使用中积累。自拟案例可以做初步检查，但不当作用户认可的实践样本。

## 2. 用同一样本，测试两种工作方式

先对齐本轮 Goal、成功条件和测试范围，作为两路的共同起点。两路使用同一版 Skill 和相同材料，独立运行，可以并行启动。

| 工作方式 | 怎样运行 | 重点观察 |
|---|---|---|
| 托管 | 对齐 Goal 后，由 Agent 在约定范围内自主推进 | 能否完成目标，判断是否合理，结果是否可靠 |
| 深入掌握 | 用户全程跟进，与 Agent 实时交流并参与关键判断 | 能否让用户理解并掌控过程，同时完成目标 |

这是同一个 Skill 的两种使用方式，不按 Skill 类型二选一。可以按约定只测部分环节；用户认为试用足够时结束，未覆盖的部分注明即可。

两路都保留实际结果与主要执行过程。实时交流由真人参与，记录新增信息和用户纠正；自主运行遇到阻塞时如实说明，不代替用户作答。若目标包含用户本人掌握，需要其解释、预测或应用表现，不能仅凭 Agent 的产物认定达成。

## 3. 对照参考，判断差异与原因

两路都按以下两层标准检查实际过程与结果，分别给出结论和证据：

| 层次 | 判断标准 |
|---|---|
| 目标是否达成 | 对照 Goal 阶段已对齐的目标、预期、约束和验收条件逐项判断，包括已约定的用户参与方式 |
| 质量：概念完整性 | 概念、术语、规则和各部分关系是否一致、连贯，有没有矛盾或含糊；完整性不等于功能齐全 |
| 质量：复杂性 | 是否存在不必要的步骤、规则、文件、依赖或抽象，是否增加理解、使用和修改的负担 |

再与参考样本比较，说明结果和关键过程有哪些差异、对目标的影响、可能原因及证据，并提出具体调整建议。参考结果帮助识别差异，不替代已确认的验收标准；没有需要改进的问题时，也可以建议不改。

不同但有效的方案不因偏离参考就判错。交互中新增的信息、人提供的修正、执行与环境都会影响结果；没有验证的原因标为推测，不把差异都归因于 Skill，也不凭一次运行判定哪种方式普遍更好。

## 4. 提供简洁报告，由用户决定修改

默认先给用户一份主报告，分别说明两路的**目标达成结论**与**概念完整性、复杂性结论**及其证据，再给出关键差异、原因依据和优化建议。每项发现附少量原文或证据定位，说明需要用户决定什么。

证据集中在三个附件，原始文件按需放在附件下的材料目录，不增加大量平级说明文件：

| 文件 | 作用与读法 |
|---|---|
| 参考样本 | 保存认可的输入、结果和主要过程，核查原始预期时阅读 |
| 本轮运行记录 | 分“自主推进”“真人跟进”两部分，保存各自完整输入、输出和主要过程 |
| 详细对比分析 | 保存两层标准的逐项判断、证据与归因依据，有疑问时查阅 |

参考样本与两路运行记录均按“任务条件—输入—主要过程—输出—限制”排列，便于在 IDE 中并排阅读。大文件可链接原样副本。报告写清各文件位置和阅读方式，日常不要求用户通读附件。

用户 Review 后决定修改内容，按已有授权实施，再针对问题复验并依约更新版本。保留修改前后结果；已用于调整的样本用于回归，后续增加新样本检查适用范围。

## 执行注意

- 参考答案、历史后续纠正和评估结论不提前交给执行者。若上下文已经包含这些内容，换用干净的执行上下文；无法隔离时标明条件，不声称是未见答案的重跑。
- 保留待测版本和真实记录，区分原文与摘要，说明缺口，不补造反馈或验证结果。试验产物与正式文件隔离，不覆盖参考样本。
- 满足约定要求或用户决定结束时收住；未达标、阻塞和未覆盖的内容如实报告，不反复重跑直到得到满意结果。
