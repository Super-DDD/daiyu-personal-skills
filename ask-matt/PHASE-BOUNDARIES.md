# 阶段边界

译自 [`ask-matt/PHASE-BOUNDARIES.md`](https://github.com/mattpocock/skills/blob/abeeaf9/skills/engineering/ask-matt/PHASE-BOUNDARIES.md)。

**阶段**是一个会话中的一段工作，例如访谈、实现或质量验证。什么时候算一个阶段结束，很难严格定义。你觉得「好，这部分做完了」时，就是它的边界。

**阶段边界**是两个阶段之间的间隔。下面的选择只在这个位置做。一个阶段做到一半时，继续推进，或把余下工作拆给 subagent。此时压缩会让 agent 丢掉思路。

## 五种选择

| 选项 | 做什么 |
| --- | --- |
| **继续** | 留在当前会话，不切换上下文。 |
| **`/clear`** | 清空上下文，从空白开始。 |
| **[`$handoff`](../handoff/SKILL.md)** | 写一份可携带的 Markdown 文件，用它在任何地方开启会话。 |
| **subagent** | 把边界清楚的任务送进独立上下文，取回报告。 |
| **`/compact`** | 压缩当前上下文，用压缩后的内容开启新会话。 |

## 决策树

从上往下判断，采用第一个回答为「是」的选项。

**1. 可以在当前会话继续吗？** 两种情况应回答「是」。下一阶段需要把当前阶段当作**一手资料**，或者 [smart zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（约 15 万 token）的余量还能容纳下一阶段。从访谈直接进入实现就是典型例子，实现需要看到原样的推理。继续不花成本，也不丢信息，所以先判断它是否可行。

**2. 当前上下文与后续工作无关吗？** 如果这里的探索、决定和走过的弯路都可丢弃，就用 **`/clear`**。它几乎不花时间，也无须交接。原会话仍能恢复。若误清了后面还要用的上下文，已做决定的理由就会从当前会话中消失，重新读 diff 也找不回来。

**3. 需要交接吗？** **`$handoff`** 只用于这几种情况。

- 换用另一套 agent harness，例如从 Claude 切到 Codex。
- 换到另一个工作目录或仓库。
- 把工作交给同事。
- 在阶段进行中分出一项旁支任务，同时让当前工作继续。

它的价值是让信息能随文件一起带走。

**4. 这项任务可以在你离开键盘时完成吗？** 如果范围足够清楚，执行时无需你随时指导，就交给**subagent**。自动审查是典型例子，subagent 读 diff 并给报告，当前会话可以继续。

**5. 其他情况用 `/compact`。** 当前上下文仍有用，agent harness和工作目录都相同，且你还要参与。可以附上一条指令，例如 `/compact 接下来要做质量验证`，让摘要保留下一步所需的信息。

`/compact` 是这棵树最后的默认选项。若一上来就用，摘要可能把有条件的决定说平，新会话会带着错误的理解继续。

## 一手资料和二手资料

除了继续之外，其他做法都会以**二手资料**代替**一手资料**，让后续工作依赖摘要或提取过的信息。

| 来源 | 信息量 | 噪声 | 可用空间 |
| --- | --- | --- | --- |
| 一手资料（继续） | 完整 | 多 | 少 |
| 二手资料（`/compact`、`$handoff`） | 有损 | 较少 | 多 |

先判断能否继续。只有继续的代价超过收益时，才接受信息损失。

这些问题需要判断。「当前上下文还是否相关」也没有客观阈值。它们的价值在于按顺序判断，而且只在阶段边界做这个判断。
