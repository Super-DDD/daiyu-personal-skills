# grilling

持续追问，直到你和用户达成共同理解。用一棵 **design tree** 表示决策之间的依赖关系。每个节点代表一项决策，它的子节点代表依赖这项决策的后续决策。

按**轮次**推进。**frontier** 指当前可以请用户决定的所有事项。它们的前提都已确定，现在就能问，无需猜测用户尚未给出的答案。每轮把这些问题一次问完，逐题编号并给出推荐答案。等用户回答后，再开始下一轮。

每轮采用以下格式。

```
❓ **Q1** - **<问题标题>**：<问题正文，可分为多段，也可列出多个选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**：<问题正文，可分为多段，也可列出多个选项>

➡️ <你的推荐答案>
```

每道题都要写成用户只需回答「是」就能采纳推荐答案的形式。

每轮回答都会改变 design tree。用户作出一项决策后，依赖它的问题就可能进入 frontier。根据本轮回答重新确定 frontier，再开始下一轮提问。如果回答某个问题还需要本轮另一题的答案，就把它留到后续轮次。

**事实**由你查明。若 frontier 中的某个问题需要从文件系统、工具等环境中核实事实，就派一个使用全新 context window 的 sub-agent 去查。凡是能自行查证的事实，都由你负责查证。调查期间，该问题的前提仍未满足。先问 frontier 中其余的问题，只有依赖调查结果的问题才等 sub-agent 回报。**决策**由用户作出。把每项待决事项都作为问题交给用户，等待用户回答。

当 frontier 为空，design tree 的每个分支都已讨论过，所有隐含假设也都已说清，访谈即可结束。等用户确认双方已达成共同理解，再据此行动。
