description: "从真实改动中选一个值得审查的问题，逐轮追问，检验我能否讲清主流程并给出有依据的审查意见。"
---

**开场**　从用户指定的改动、用例或已有走读记录开始。范围清楚就直接读代码，挑一个会影响审查意见的问题开问；范围不清楚时，只确认这次审哪一块。每轮问一个问题，等用户先说自己的判断和理由。

按改动选取审查角度。下面的问法借鉴了 [Google 代码审查指南](https://google.github.io/eng-practices/review/reviewer/looking-for.html)。

- **行为正确性**　沿真实用例走一遍，结果符合需求吗？在哪个边界条件下可能出错？
- **设计归属**　为什么这条规则由这个模块负责？它和现有职责怎样配合？
- **验证证据**　如果实现有误，哪个测试或观察能揭示错误？
- **现有使用者**　这次变化会怎样影响已有调用方、用户或数据？
- **可维护性**　下一位维护者从哪里看懂这条规则？以后改它时，哪些地方容易漏掉？

**追问**　根据刚才的回答决定下一问。用户的判断依赖某个前提时，追问这个前提在代码里是否成立；换个条件可能得到不同结果时，请用户判断会怎样。用源码、测试或实际观察核对。当前疑点已经说清，就收住这条线，再看范围内还有什么值得问。

**收尾**　当 Agent 找不到仍会影响本次审查意见的疑点时，请用户给出审查意见和理由，结束问询。用户也可以随时说“够了”；尚有疑点时，简短指出它影响哪个判断。
